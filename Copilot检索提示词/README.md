# Copilot 检索提示词（Work IQ）

让 Microsoft 365 Copilot 在查邮件、Teams、公司文件时找得准、总结得准，重点对付版本、分支、变更这类容易混在一起的内容。

模板里的【客户X / 分支Y / 功能Z】换成实际名称再用。每个模板有中文版和日文版，内容相同。

## 先看这三条

1. **规则要短。** 规则越多，每条执行得越差；检索词是从整段话里生成的，规则文字多了检索词会跑偏。
2. **力气花在问题本身。** 名称照抄资料原文，写清时间范围和来源，比加规则管用。
3. **让它出表格。** 每行一条事实、带版本和出处，不同版本的内容就揉不到一起，哪行混进来了一眼能看到。

## 问题怎么写

| 要写的 | 写法 |
| --- | --- |
| 版本 / 分支 | 一次只问一个，名称照抄资料原文（日语、型号、分支名），不用口头叫法 |
| 时间范围 | 例："2024 年以后" |
| 来源类型 | 例："邮件和設計書" |
| 人名、文件名 | 知道就写上 |

## 模板 A：查某个版本的功能、规格

中文

```
只查【客户X / 分支Y / 功能Z】，邮件、Teams、文件都要查。
先用表格输出，每行一条事实：
内容｜所属版本・分支｜日期｜来源类型｜状态｜出处链接
来源类型：正式资料／邮件／Teams
状态：已决定／讨论中／不明
规则：
1. 版本不明的写"不明"，不许算到分支Y头上
2. 不同版本的说法分行写，不许合并
3. 说法冲突时：正式资料 > 邮件 > Teams；同类来源取日期最新的，并标出被覆盖的那条
4. 邮件串只取最后的结论，引用的旧内容不单独算一条
5. 表格之后写结论，只用"分支Y + 已决定"的行；"讨论中"的另列为待确认
```

日本語

```
【顧客X / ブランチY / 機能Z】についてのみ調べてください。メール、Teams、ファイルのすべてを検索対象にしてください。
まず表で出力してください。1行に1つの事実：
内容｜対象バージョン・ブランチ｜日付｜種別｜状態｜出典リンク
種別：正式資料／メール／Teams
状態：決定済み／検討中／不明
ルール：
1. バージョンが分からないものは「不明」と書く。ブランチYのものとして扱わない
2. バージョンが違う内容は行を分ける。まとめない
3. 内容が食い違う場合：正式資料 > メール > Teams。同じ種別なら日付が新しい方を採用し、上書きされた行を明記する
4. メールスレッドは最後の結論だけを採用する。引用された過去の文面は1件として数えない
5. 表のあとに結論を書く。結論に使えるのは「ブランチY かつ 決定済み」の行だけ。「検討中」は要確認事項として別にまとめる
```

## 模板 B：查变更历史

中文

```
按时间列出【功能Z】的所有变更，邮件、Teams、文件都要查：
日期｜变更前 → 变更后｜适用哪些分支｜状态（已决定／讨论中）｜出处链接
适用分支不明的写"不明"，不要推测着填。
```

日本語

```
【機能Z】の変更履歴を時系列で一覧にしてください。メール、Teams、ファイルのすべてを検索対象にしてください：
日付｜変更前 → 変更後｜適用ブランチ｜状態（決定済み／検討中）｜出典リンク
適用ブランチが分からないものは「不明」と書いてください。推測で埋めないでください。
```

## 模板 C：两步法（最稳，重要的问题用这个）

第 1 条消息只让它列资料，不回答。自己挑出对的几份，第 2 条消息再让它只根据这几份回答。

中文

```
第1条：
关于【客户X / 分支Y / 功能Z】，先不要回答。
只列出找到的候选资料，邮件、Teams、文件都要查：
编号｜标题｜日期｜作者｜来源类型｜链接｜和问题的关系（一句话）

第2条：
只根据第 2、5 份回答，其他资料不要用。每句结论后面标出依据的是哪一份。
```

日本語

```
1通目：
【顧客X / ブランチY / 機能Z】について、まだ回答しないでください。
見つかった候補資料だけを一覧にしてください。メール、Teams、ファイルのすべてを検索対象にしてください：
番号｜タイトル｜日付｜作成者｜種別｜リンク｜質問との関係（1文）

2通目：
2番と5番の資料だけに基づいて回答してください。他の資料は使わないでください。結論の各文の後ろに、根拠にした資料の番号を書いてください。
```

## 自定义指令（只放一句）

位置：Copilot Chat → Settings → Personalization → Custom instructions。它对所有对话生效，所以只放一句短的，完整模板在查资料时再贴。

中文

```
涉及版本、分支、变更时，每条事实标明所属版本、日期和出处，不明的写不明，不同版本不合并。
```

日本語

```
バージョン、ブランチ、変更に関する内容は、事実ごとに対象バージョン・日付・出典を明記し、分からないものは「不明」と書き、バージョンが違う内容はまとめないでください。
```

## 表格出来后看什么

- **所属版本**一列里有没有别的分支混进来。
- **不明**的行有几条。多的话，换更准确的名称再问一次。
- **状态**是"讨论中"的行，不能当成已实施的变更回答别人。
- 链接点开核对。它自己写的检索词、检索过程只当线索，以链接里的原文为准。
- 邮件比正式资料新，而且写着已决定：通常是资料还没更新，以邮件为准，记一笔"资料待更新"。

## 三类来源各自的坑

| 来源 | 坑 |
| --- | --- |
| 正式资料（仕様書、設計書、変更履歴） | 同一份文件有多个旧版副本，要看版次和日期 |
| 邮件 | 回复串里引用了大量旧内容，早期提案容易被当成结论；结论通常在最后几封 |
| Teams | 片段化，很少写明是哪个版本，多数是讨论中的想法 |
