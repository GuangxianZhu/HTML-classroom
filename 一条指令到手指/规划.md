# “一条指令到手指”的规划

2026-11-11 定的方案。起因：想把 GitHub 上 whj_MCU 项目做成 HTML 演示 + Blender 建模，放进 HTML-classroom。动手前用选择题确认了三件事和一份关卡表。

## 确认过的选择

| 问题 | 选了什么 | 没选的 |
| --- | --- | --- |
| 主题 | **一条指令的全程**：从电脑发出一个角度，到手指弯曲，把整个项目串成一条线 | 只讲腱绳手指；只讲半双工总线；只讲六块 M7C |
| 讲法 | **零基础闯关**：一关只引入一个新概念，先猜再动手（和 GPIO 引脚实验台一样） | 分章原理 + 实验；爆炸图为主 |
| 规模 | **大：十关以上**，多个 Blender 模型 | 3–4 关先出一版；6–8 关 |
| 关卡表 | 按十四关做（下面这张；11 月 12 日把第 8 关拆开，现在是十五关，见文末） | 机械侧加重；通信侧加重；先只看方案 |

## 三种主题的取舍

- **一条指令的全程（选了）**：好处是把仓库里散在几十份文档里的东西排成一条线，以后查问题知道该去哪一站。代价是每一站讲得浅，细节要回 whj_MCU 看。
- **只讲一块**（腱绳、总线或多板）：能讲深，但仓库里已经有爆炸图和避坑课，通信那一块会重叠；而且只看一块，看不出各块是怎么接上的。
- 这一页和 whj_MCU 里已有的两页分工：这里讲“每一站为什么是这样”，避坑课讲工程习惯，爆炸图讲实物接线。

## 关卡顺序

跟着一条指令“食指 MCP 弯到 45°”走，顺序就是信号走的顺序。

1. 全程地图：先猜时间花在哪，再看十站
2. 角度变成电机位置数（标定）
3. 数装进数据包
4. 字节变成高低电平（UART、波特率）
5. M7C 转发
6. 3.3 V 变 5 V（TXB0104）
7. 两根线合成一根（241、DIR）
8. 17 个舵机谁来听（ID、应答、Return Delay、TXEN 松手时机）
9. 舵机内部（位置环、齿轮、编码器、电流上限）
10. 线轴拉腱绳（线长守恒）
11. 预紧和回差
12. 读回来和时间账
13. 六块 M7C
14. 全程回放 + 排查题

## 设计假设

- **一关一个新概念**。GPIO 那一页试用后发现，一关里同时出现几个新东西就看不懂，这里沿用拆细的做法。第 8 关放了两件事（谁来听、TXEN 什么时候松手），因为第二件离不开第一件；如果看着吃力，以后拆成两关。
- **用仓库里真实发生过的事当例子**：下拉电阻插成 10 kΩ、地线分两条轨引起回显、波特率自动探测误判、绳结脱出。每条标明是实测、推断还是读源码得出的。
- **数字从模型里算，不手写**。`web/src/core.js` 是唯一的数字来源，`test_core.mjs` 拿仓库里的已知数据包和时间表去对。
- **三个模型分开**：桌面全景看“在哪”，舵机剖视看“里面”，一根手指看“线怎么走”。模型外形都是为了讲原理自己画的简化版。
- **每关末尾写依据**：公认 / 手册 / 仓库实测 / 推断 / 估算 / 示例数字，分开标。
- 成品是一个 HTML 文件，双击就能打开，带 Windows 一键启动 bat，启动时检查 main 更新。

## 做的顺序

先写 `core.js` 和校验（24 项全过），确认数字和仓库对得上；再建三个 Blender 模型；然后先做前五关接上舞台，用无头浏览器看过没问题，再补后九关；最后逐关点一遍、看手机宽度。

## 2026-11-12 改动：“TXEN 什么时候松手”单独成一关

试用反馈：原第 8 关的实验二没看懂。回头看，问题有五处：

1. **一关塞了两件事**。“谁来听”和“什么时候松手”挤在一起，前面已经记下“看着吃力就拆”。
2. **图画的是波形**。三行细小的方波加微秒刻度，要先会读波形、对 µs 有感觉才看得懂，而这两样都没教过。
3. **术语先于现象**。按钮上直接写“发送完成标志”“缓冲区空标志”，点之前不知道它们是什么。
4. **缺一个“为什么按着就不行”的说法**。TXEN = 1 时发送门占线、接收门关着，只在前一关出现过一次。
5. **结果是一段带一串数字的话**（−17 µs、517 µs），重点被细节盖住。

改法：

- 拆成两关，一共十五关。第 8 关只讲 ID 认领；新的第 9 关“什么时候松开说话键”。
- 用对讲机打比方：按住说话键才能说，按着的时候听不到对方。TXEN 全程叫“说话键”。
- 图不画波形，改成**一个方块一个字节**：橙色是指令，蓝色是应答，红色斜纹是坏掉的部分；时间用“发几个字节的时间”来比，不要求对 µs 有感觉。
- 分三步，一步只加一样东西：只看一问一答 → 加上说话键和“可以松手的空当” → 舵机的等待从 500 µs 改成 20 µs。
- 按钮先用大白话（发完马上松 / 最后一个字节还没发完就松 / 发完又多按了 1 ms），看过现象以后，再用一张表对上固件里的写法（TC、TXE、固定延时）。
- 加“播放这一次”：时间线从左走到右，上面模型里的线跟着变色（橙 = M7C 在说，绿 = 舵机在答，红 = 撞上了）。
- “停止位里提前松也没事”这个细节挪到最后的小字里。
- 关卡编号不再写死：文案里用 `lv('key')`，以后再拆关不用到处改数字。
