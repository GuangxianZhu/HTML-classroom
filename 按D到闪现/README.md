# 按 D 到闪现

从在英雄联盟里按下 D 键，到屏幕上看到英雄闪现，一次按键的往返经过哪 12 站、各花多久、谁说了算。通信原理教学页，离线单文件，没有外部依赖。

## 怎么打开

- **Windows**：双击 `启动演示.bat`。它先检查 `main` 分支有没有更新，有就 `git pull --ff-only`，然后用默认浏览器打开 `index.html`。
- **其他系统**：直接打开 `index.html`。

## 页面里有什么

1. **开场猜题**：按 D 到看见闪现，时间大头花在哪。猜完（或点「不猜了」）才解锁后面。
2. **信号之旅**：12 站路线图 + 分步手册。每站只回答一个小问题，标题就是答案，每站有自己的小动画，顶部计时器按典型耗时累加。
   键盘矩阵 → USB 轮询 → 操作系统 → 客户端读输入 → 打包命令 → 协议栈/网卡 → 家里的路由器（NAT）→ 运营商和骨干 → 服务器 tick 判定 → 广播回传 → 客户端渲染 → 显示器扫描。
3. **实验 1 延迟预算**：拖键盘轮询率、帧率、刷新率、垂直同步、Ping、tick，看总延迟和各段占比。
4. **实验 2 丢包抖动**：连按 20 次 D，看 UDP 和 TCP（队头阻塞）下每次按键到生效的时间。
5. **第二道猜题 + 实验 3**：两个人同时闪现谁先，三条时间轴，服务器只认到达时刻和 tick。
6. **前提与失效条件、其他路线（服务器权威 / 客户端预测 / 锁步）、证据强弱、来源**。

每句结论后面有证据标签：公认 / 资料 / 估算 / 推测。凡是「LoL 内部怎么做」的句子最高只标到「资料」。

## 结论和它的边界

- 典型配置（有线 1000 Hz 键盘、144 Hz 显示器、同区 Ping 40）下，按 D 到看见闪现约 80 ms，其中网络往返 + 等服务器 tick 占一半以上，渲染到显示其次，键盘和操作系统加起来只有几毫秒。这是估算，不是实测。
- 服务器 30 tick/s 来自 LoL 社区 wiki，Riot 自己的博客没写；游戏走 UDP 5000–5500 / 7000–8000 有 Riot 支持页为证；「客户端不预演闪现」没有明文，标推测。
- 实验 2 的 TCP 模型是简化的（丢包后约 1 RTT + 20 ms 重传，后续包等它），只用来说明队头阻塞。
- 实验 3 的 tick 相位是固定的；同一 tick 内谁先处理，本页不知道。
