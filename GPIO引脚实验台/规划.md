# GPIO 演示的规划

2026-11-10 定的方案。起因：看完文字解释（GPIO 是什么、代码怎么控制引脚、引脚和寄存器位的对应）之后，还是不清楚具体怎么实现，想从头学。

## 目标

GPIO 难懂的地方不在“长什么样”，在“代码 → 寄存器 → 开关 → 电压”这条看不见的因果链。所以演示的核心是：亲手改一个位，立刻看到引脚变化。Blender 模型负责让它看起来像桌上的真板子。

## 三种做法和取舍

| 做法 | 好处 | 代价 |
| --- | --- | --- |
| A 纯 2D 动画 | 因果链最清楚，做得最快；网上的 GPIO 教学大多是这种 | 不像实物，代入感弱 |
| **B 三维开发板 + 2D 内部（选了这个）** | 板子像真的，内部原理用 2D 讲清楚 | 多花建模时间 |
| C 全三维 | 最炫 | 芯片内部本来就是抽象的，硬做成三维反而难懂，工作量最大 |

## 关卡顺序

每关只讲一件事，前一关懂了再进下一关。

1. 高低电平：电压像水压，3.3 V 是 1，0 V 是 0
2. 引脚里面有什么：两个开关，一个接电源，一个接地
3. 寄存器：一排 8 个格子，每格连着一个引脚的开关
4. 代码登场：一行代码，单步执行，看数沿着总线流到寄存器再到引脚
5. 输入：按键、悬空乱跳、上拉后稳定
6. 配置和踩坑：先设方向再输出；故意忘开时钟
7. 进阶：开漏、读改写被中断打断、置位寄存器

## 设计假设

- 用一颗虚构的简化芯片：1 个端口、8 个引脚、每项配置每个引脚 1 位。真实芯片细节太多会淹没主线；代价是学完要对照一次手上芯片的手册。差别列在 README 里。
- 电流、电压只做定性表现（亮和灭、流动的光点），不做精确仿真。
- 成品是一个 HTML 文件，双击就能打开，带 Windows 一键启动 bat，启动时检查 main 更新。

## 制作顺序

先做第 2、3 关的 2D 原型试看，确认讲法能看懂；再补其余关卡；最后建 Blender 模型接上去。讲法不对的话，不会浪费建模的工夫。

## 试用后的修改（2026-11-10）

原来的第 4 关（代码单步）没看懂，卡在四个地方：0x21 这种数、地址和总线、一次变的东西太多、`|=` 和 `&= ~`。原因是一关里同时出现了四个新概念。改法是拆成四关，每关只引入一个：

- 数的写法：十六进制只是“每 4 位一组的简写”
- 地址：门牌号和信的比喻，总线是送信的路
- 代码：只留三行赋值，四站依次点亮，一次只看一站
- 改一位：用“点名”解释 `|=` 和 `&= ~`，再引出读、改、写三步

总数从七关变成十关。以后加新关卡也按这个原则：一关只出现一个新东西。
